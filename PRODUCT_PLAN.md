# План разработки: антигравити — шагомер с атмосферой

## 0) Краткое видение
**Цель:** мотивировать больше ходить через атмосферные миры и награды за достижение локаций. Пользователь выбирает вселенную, проходит реальные расстояния на реальной карте, получает награды за «достопримечательности», отвечает на вопросы по лору и копит баллы для магазина скинов.

**Платформы:** iOS + Android.

**Источники данных:** Apple Health / Google Fit с регулярной синхронизацией шагов, дистанции, времени активности и калорий.

**Графика:** реалистичные изображения, генерируемые ИИ — для каждого дня и каждого этапа.

---

## 1) MVP: что делаем первым
### 1.1 Функции
1. **Авторизация** (почта/Apple/Google) + выбор мира (Средиземье / WoW / Ведьмак).
2. **Синхронизация шагов** из Apple Health / Google Fit (фоновая + ручная).
3. **Динамический прогресс** по реальным расстояниям (шаги → км → локации на карте).
4. **Лента дня**: сколько пройдено, какая локация достигнута, изображение дня.
5. **Лор‑квиз** при достижении ключевых локаций (начисление очков).
6. **Награды**: очки за локации + правильные ответы.
7. **Мини‑магазин (MVP)**: каталог скинов (без оплаты, только за очки).

### 1.2 Почему так
Это закрывает основные потребности:
- мотивация ходить (прогресс + награды),
- атмосферность (мир + визуал + лор),
- простая механика (шаги → расстояние → локации → награды).

---

## 2) Пользовательский сценарий (end‑to‑end)
1. Устанавливает приложение.
2. Выбирает мир (например, Ведьмак).
3. Подключает Apple Health / Google Fit.
4. Каждый день видит прогресс: расстояние, карту и текущую локацию.
5. Достигает знаковой точки → появляется вопрос по лору.
6. Правильный ответ → награда + очки.
7. Накопленные очки тратит в магазине на скин.

---

## 3) Техническая архитектура (черновик)
### 3.1 Клиент
- **Кроссплатформенный фреймворк:** Flutter или React Native.
- **Карта:** Mapbox или Google Maps SDK.
- **Здоровье:**
  - iOS — HealthKit (через нативный мост),
  - Android — Google Fit.

### 3.2 Бэкенд (MVP)
- **API:** REST/GraphQL (Node/Express или FastAPI).
- **Хранение:** PostgreSQL.
- **Сервис генерации изображений:** отдельный воркер (queue + job).

## 4) Модель данных (упрощенная)
- **User**: id, email, world_id, total_points
- **World**: id, name, theme
- **Location**: id, world_id, name, lat, lng, distance_km, lore_question_id
- **DailyProgress**: user_id, date, steps, distance_km, calories, duration
- **Reward**: id, user_id, location_id, points_awarded
- **Skin**: id, name, price_points

---

## 5) Динамика локаций
**Принцип:**
- Каждая вселенная имеет список ключевых точек.
- Прогресс пользователя = сумма шагов → км → сравнивается с дистанцией локаций.
- Когда пользователь «дошел» до локации → награда + лор‑квиз.

**Реальные расстояния:**
- Используем реальные координаты.
- Расстояние считается по реальной географии (км по карте).

---

## 6) Генерация изображений
**MVP‑подход:**
- На каждый день → 1 изображение на основе текущей локации.
- На каждую новую локацию → отдельный арт.

**Пример промпта:**
> “Realistic cinematic landscape of [location_name] in the world of [world], sunrise, epic scale, detailed environment.”
